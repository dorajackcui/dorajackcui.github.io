# YIZHI · 通用视觉参考

版本 1.1 · 2026-09-15 · 浅色界面

基准：正式 landing page（`index.html`），采用 Inter、橙色品牌句点和统一产品插画，首屏不再放重复的「查看项目」入口。借鉴 Notion 的中性色、无衬线排版和留白。本规范适用于网站、Web 应用和桌面应用。

这是一份视觉参考，不是一套页面模板。迁移时，保持目标产品的功能、信息架构和主要工作流程。

## 1. 核心原则

- **内容优先。** 标题、正文、数据和实际工作区构成主体，装饰保持克制。
- **一个区域最多三个主要元素。** 每个 section 只讲一件事，例如「标题、说明、操作」。多余内容先删重复、合并说明，再按用途拆分。
- **中性色为底，橙色点睛。** 白色主背景、深灰文字、极浅灰辅助区域；品牌句点用暖橙色。其他颜色服务于状态和内容。
- **通过排版建立层级。** 先调整字号、字重、间距和对齐，再考虑增加边框、卡片或底色。
- **用间距组织内容。** 同组紧凑、组间清楚；有真实分组需求时才用分隔线。
- **交互有明确反馈。** 安静的视觉仍须让用户分清可点击、选中、聚焦、禁用、处理中和错误状态。
- **文字只承担必要的信息。** 名称、用途、操作、结果；不补写自我介绍、口号或庆祝感言来填空。

统一的是视觉基础和控件细节。导航位置、内容宽度、面板数量和信息密度由任务决定。

## 2. 通用颜色

以下角色可直接用于不同技术栈。CSS 和 JSON 文件提供相同的值。

| 角色 | 值 | 使用方式 |
| --- | --- | --- |
| 页面背景 | `#FFFFFF` | 主页面、主要工作区 |
| 辅助表面 | `#F7F7F5` | 预览衬底、已有侧栏、轻量分组、悬停背景 |
| 主文字 | `#2F2F2C` | 标题、正文、重要值、主要操作 |
| 次要文字 | `#707068` | 描述、标签、次级信息；小字优先使用此色 |
| 品牌强调色 | `#D97757` | `YIZHI.` 的句点；少量品牌标记和重点细节 |
| 装饰分隔线 | `#E9E9E5` | 区域分隔和图片轻边框；不承担唯一的交互识别 |
| 控件边界 | `#85857C` | 需要边界来识别的输入框等；建议适配值 |
| 链接细线 | `#B6B6AC` | 可选的文字链接下划线 |
| 键盘焦点 | `#2383E2` | `focus-visible` 外轮廓；不是页面主品牌色 |

**颜色使用方式：** 避免用多种彩色背景区分每个模块。成功、警告、错误、译文差异等语义色保留目标产品原有含义，控制面积，并同时提供文字或图标说明。真实截图和内容可以保留自己的颜色。

### 品牌句点

`YIZHI.`：字母保持深灰，末尾的 `.` 使用暖橙 `#D97757`，沿用文字的字重和基线。句点是主要品牌识别细节。色值先参考 [Claude Academy 的橙色示例](https://academy.claude.com/use-cases/package-your-brand-guidelines-in-a-skill)，后续更换时只调整品牌色变量。

- 句点可以作为小面积的品牌标记延伸到不同产品，不必把产品名称统一改成 YIZHI。
- 展示用产品标题同样延续句点：`momoCAT.`、`QAtools.`、`Tool Hub.`。只给末尾句点着色；代码标识、文件名和正文中引用的产品名称无需加点。
- 在标识、一个重点细节或选中标记中少量使用；一屏无需重复铺满橙色。
- 正文、所有链接和按钮不自动染橙，保留中性色主导的阅读秩序。
- 品牌色与错误、警告、运行状态分开命名；橙点本身不代表未读或错误。
- 原始暖橙不用于白底小字，也不默认配白色小字按钮。功能性用色仍需满足对比度，品牌标记不要承担唯一的状态提示。

**基准与通用化的差别：** 首页使用 `#787871` 作为部分说明灰色，在白底上的对比度约为 4.45:1；部分细小元信息更浅。通用规范采用首页已有的正文灰 `#707068`（约 4.99:1）作为默认次要文字，避免把浅灰小字带进高密度应用。正文文字目标至少 4.5:1；元信息也不自动豁免。参见 [W3C 对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。

## 3. 字体与层级

基准页面的英文与数字使用 **Inter**，中文使用系统黑体回退。Inter 的可变字重便于控制大标题与应用正文的轻重；字体说明与许可见 [Inter 官方网站](https://rsms.me/inter/)。

```css
font-family: "Inter", -apple-system, BlinkMacSystemFont, "Segoe UI",
             "PingFang SC", "Microsoft YaHei", sans-serif;
font-optical-sizing: auto;
```

现有产品已有合适的无衬线字体时，可以保留；统一层级和视觉密度更重要。下载包的 `fonts/` 提供 Inter 与许可证，可自托管；不使用它时移除 CSS 中的 `@font-face`，改用目标平台字体。不同平台的渲染不会完全一样，需要在目标平台检查。

| 用途 | 建议字号（CSS px） | 字重 | 行高 |
| --- | --- | --- | --- |
| 展示型首页主标题 | 48–80；小屏可降至 38 | 600–650 | 1.1–1.2 |
| 应用页面标题 | 24–32 | 600–650 | 1.2–1.35 |
| 区域标题 | 18–24 | 600 | 1.3–1.4 |
| 正文 / 编辑内容 | 14–16；长文可到 18 | 400 | 1.5–1.8 |
| 按钮 / 输入 / 导航 / 表格 | 13–15 | 400–500 | 1.4–1.6 |
| 次要元信息 | 12–13 | 400 | 1.4–1.6 |

- 展示性英文大标题以 `-0.025em` 为起点，小屏为 `-0.02em`；字母要清楚分离，避免重字重叠加大幅负字距。
- 中文标题、正文、表格和代码保持正常字距。其他字体先用正常字距，再按实际字形微调。
- 大面积文字避免使用过细字重。强调依靠有限的加粗，不把整页文字都加粗。
- 长文行高可以宽松；表格、编辑器、属性面板采用较紧凑的行高。
- 插画中不嵌入文字；需要展示截图时，截图字号不作为应用字号参考。
- 原生应用按平台的逻辑单位和文字缩放机制适配，不把 CSS px 数值机械当作所有平台的 pt。

## 4. 间距与密度

### 一个区域最多三个主要元素

每个 section 只讲一件事，同一区域最多放 3 个主要元素，例如「标题、说明、操作」。多出来的内容，先删重复、合并说明，再按用途拆分。

项目介绍只保留标题、一句说明和一个入口；省去非必要的序号、分类，把应用类型并入说明。同类数据集中呈现，保留必要字段和状态，三元素原则不限制数据行数。

### 间距

新界面优先使用这组间距：

`4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 80`

这是通用化后的建议阶梯，不要求把现有页面逐像素改成倍数。保持相邻元素的关系一致。

| 关系 | 常用范围 |
| --- | --- |
| 图标与文字 | 8–12 |
| 标签与对应内容 | 4–8 |
| 相关控件之间 | 8–12 |
| 组内段落或表单项 | 12–16 |
| 面板内边距 | 16–24；紧凑面板可为 12 |
| 相邻内容组 | 24–32 |
| 大区块之间 | 48–80，主要用于展示页 |

### 根据任务选择密度

| 类型 | 建议应用方式 |
| --- | --- |
| Landing page / 产品官网 | 清晰首屏、顺序展示、少量导航、宽松区块间距，内容宽度通常 960–1200 |
| 文档 / 阅读页 | 正文优先，按阅读长度限制行宽，约 60–75 个拉丁字符或 30–40 个汉字，按字体调整 |
| 编辑器 / 翻译工具 | 保留多栏和上下文面板；正文 14–16，工具栏紧凑，边距留给真正的分组 |
| 表格 / QA / 管理工具 | 保留筛选、批量操作与结果表；常见行高 32–40，必要时使用紧凑密度 |
| 小型实用工具 | 输入、主要操作、结果就近排布；不要为了留白把工作流程拆得很远 |

不同产品不必采用相同列数、相同侧栏、相同卡片或相同内容宽度。App 的实际阅读、编辑和操作效率优先。

## 5. 表面、边框与图像

- 默认平面布局。只在实际的分组、输入、预览或浮层上建立容器。
- 边框一般为 1px；分隔线使用低对比中性色。输入框边界需要足够清楚。
- 控件、小图片圆角以 4px 为起点；较大的预览区域 6–8px。圆角不成为视觉主题。
- 不默认给所有卡片加阴影。截图可使用极轻阴影；浮层若需表达层级，可以适量加强。
- 图片保持比例。展示页可以用统一的产品概念插画；需要证明具体功能或操作流程时使用真实截图。插图的替代文字说明其性质，不把概念图描述成实际界面。
- 图标统一线宽和视觉大小，通常 16–20px。只在帮助识别、导航或表达操作时使用。

可选截图阴影：`0 3px 13px #24241506`。这是很弱的图片层次；当前产品插画不额外叠加 CSS 阴影。

### 产品插画

产品名称、介绍与链接由页面文字承担；**配图不重复标题，也不加入说明文案**。图像通过文档、检查、括号等意象表达工具用途。

- 页面以中性色为主，配图可以更丰富。图片不必被限制在黑白灰或品牌橙里。
- 当前样例共用哑光纸张材质、简洁几何形状、柔和阴影和清晰构图。momoCAT 使用暖杏底，QAtools 使用淡蓝底，Tool Hub 使用浅绿底；钴蓝与珊瑚橙作为相呼应的细节。
- 统一的是视觉技法、质感、构图密度与图片比例，不是让三张图换个名字套同一个图案。
- 当前图片为 1536 × 1024，3:2。完整展示主体，保持比例，不把图片内的物体截断。
- 色彩可以活跃，但每张图保持一个明确主题和足够留白。避免堆砌大量小图标、角色或无关装饰。
- 图像属于品牌概念表达，不冒充软件界面。需要证明具体操作时，另外使用真实截图。
- 这是插画方向的样例，不要求不同类型应用都放装饰图片。工作区仍以内容和操作为主。

三张插画通过内置 imagegen 生成，生成提示保存在 `IMAGE-PROMPTS.md`。构图探索参考过 [beautify-github-readme](https://github.com/oil-oil/beautify-github-readme)，最终页面把标题与图片分开，使用无文字彩色插画。

## 6. 链接、操作与状态

### 导航与跳转

使用简洁文字链接，必要时加细下划线。目标内容已直接可见时，省去重复的跳转入口；当前首页因此移除了「查看项目 ↓」。产品链接保留细下划线。箭头仅在说明方向或外部跳转时使用，不作为每个链接的固定装饰。

### 执行操作

“运行”“保存”“导出”等是按钮行为，应保留按钮语义和明确的点击区域。可使用文字、细边框或少量深灰实心按钮，按操作层级选择。**首页跳转链接不做厚重按钮，不等于所有应用都取消按钮。**

不要让每个操作都成为深色主按钮。同一区域通常只有一个突出操作，其余保持轻量。

### 输入、表格与选中

- 保留表单标签、键盘行为、校验和错误说明。占位文字不代替标签。
- 表格先保证对齐、阅读密度和选择状态；行悬停用浅表面色，选中要能与悬停区分。
- 原有错误、警告、差异高亮、未保存状态等不能因为改成灰色风格而消失。
- 禁用、处理中、空结果都用简短、准确的状态信息。正常运行时不增加庆祝或自我介绍文案。

### 键盘与触控

焦点参考：`2px solid #2383E2`，offset 3–5px；不因“极简”去掉焦点。图标按钮提供可访问名称。触控区可通过无形内边距扩大，不必把图标本身画大；移动端优先约 44px 的舒适点击区域，这是本参考的建议值，具体最低要求和例外参见 [W3C 目标尺寸说明](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)。

## 7. 动效与文字

- 反馈动效以 120–200ms 为主，轻微颜色或位置变化即可。
- 文字链接无需漂浮、发光或持续运动。
- 首页插画悬停以 150ms 轻微改变透明度；数据表行和编辑区域保持稳定。
- 遵循 `prefers-reduced-motion`，动画不成为理解内容的必要条件。
- 用具体名词和动词：项目、文件、检查、导出、重试。错误说明指出问题和下一步。
- 展示页每个产品优先一两句事实描述。复杂应用仍要提供必要帮助，不能为了少字隐藏关键操作含义。

## 8. 迁移方式

1. 确认目标是展示、阅读、编辑还是数据处理，保留其结构和任务路径。
2. 把颜色映射到语义角色，再统一字体层级和间距。
3. 先选一个有代表性的真实页面，覆盖正常、有数据、错误或空状态。
4. 调整链接、按钮、输入框、表格、焦点和选择反馈，复用目标项目已有组件。
5. 检查不同文字长度、中文和英文、小屏、缩放及键盘操作，再扩展到其他页面。

跨平台共用的是角色、比例与行为。无需为了统一视觉迁移技术栈。本文没有定义新的导航系统、深色主题或全套语义状态色；这部分按目标产品已有能力处理。

> 请参考所附《YIZHI · 通用视觉参考》调整当前项目：
>
> 1. 调整范围：保留原有产品名称、功能和主要流程，布局与密度按实际任务安排。
>
> 2. 视觉与层级：使用白底、深灰文字、浅灰辅助区、无衬线字体和清晰的间距，品牌句点用暖橙色 #D97757。每个 section 只讲一件事，同一区域最多放 3 个主要元素，例如标题、说明、操作。多余内容先删重复、合并说明，再按用途拆分。
>
